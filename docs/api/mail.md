# 邮箱与草稿接口契约

对应[开发设计](../MVP开发设计.md)。沿用[通用 HTTP 约定](tasks.md#http)。每个草稿修订绑定所有收件人、主题、正文、附件名称及不可变内容，内部核对引文单独返回。

## E01

`TaskId sync(AccountId account, RequestKey key)`，由后台周期调用。例如 同步账户 a1 两次 → 已有邮件仍一份，草稿和拟稿任务新增零条。认证失败返回任务错误，保留原游标。服务恢复后继续。回复头指向已知邮件时归入该往来，单凭同主题不足以合并。手机用 `GET /threads` 查看往来列表。

## History

邮件模块公开 `ThreadView history(ThreadId thread, MessageId through)`，读取截至指定来信的往来及正文。例如 `history(h1,m2)` → [m1,m2]。`GET /threads/h1?through=m2` 提供同一视图。来信不存在或不属此往来返回 404。只读。后续追问不改变选中来信的范围。E02 用此接口与[资料检索](knowledge.md#retrieval)准备上下文。

## E02

`DraftResult manage(DraftCommand command)`，按操作返回任务、草稿或放弃状态。

| 操作 | 示例输入 | 返回、副作用与重复操作 |
|---|---|---|
| 拟稿 | `POST /threads/h1/drafts`，来信 m2、请求键 g1 | 202、任务号。只在用户操作后生成。同键或同一来信正在拟稿时复用任务。历史或资料不可用时区分服务失败与无相关材料。 |
| 预览 | `GET /drafts/d1` | 返回版本、完整外发内容及独立的核对引文。再次读取无写入。 |
| 保存 | `PATCH /drafts/d1`，修订 2、编辑内容、请求键 e1 | 返回已保存修订 3。相同请求重试返回原结果。其他过期编辑返回 409 和最新修订。 |
| 放弃 | `DELETE /drafts/d1`，预期修订 3、请求键 x1 | 记录已放弃，重复调用返回既有结果。草稿锁定时返回 409。保存、放弃均无外发。 |

生成结果仅在草稿仍可编辑且预期修订相符时写入。历史里出现新追问提示用户查看，保留手工编辑。缺少个人资料支撑时在核对区提示证据缺口。附件读取失败时提示修正，禁止确认不完整快照。

拟稿请求体为 `{messageId}`，保存请求体为 `{revision, content}`，放弃请求体为 `{revision}`。`content` 含 `to`、`cc`、`bcc` 地址数组、`subject`、`body` 和附件数组。附件用 `{name, base64}` 上传，预览只返回名称和字节数。已有附件在保存时可按相同草稿修订的 `{name, index}` 保留。已明确发送失败的草稿可用 PATCH 创建下一修订。

每份草稿最多 10 个附件，合计至多 8 MiB。

## E03

`SendView confirm(DraftId id, Revision reviewed)`，只接受本人独立确认操作。例如 `POST /drafts/d1/send` 带修订 3 → 202、发送记录 s1。预览或修改均不触发此调用。已提交的同一确认始终返回已有记录。过时且未提交的确认、已放弃的草稿返回 409。确认后禁止修改已锁定版本。收件人包括抄送与密送。发送时使用冻结的附件字节，外发正文以确认预览为准。

`GET /sends/s1` 查排队、发送中、已发送、失败或待核对。取得发送权后若进程中断、回执丢失或部分收件人已被接受，停止重投，核对服务商记录和 Message-ID。证据不足时保留待核对。可确定未被接受才显示发送失败。重复确认及重启均沿用原记录。外发前已明确失败者可由用户核对、生成新修订后再次确认。

确认请求体为 `{revision}`。`GET /sends/{id}` 对应唯一发送记录，`GET /sends?draftId=d1` 列出相关记录，省略筛选项时返回本人的发送记录。手动收信使用 `POST /mail/sync`，携带请求键。
